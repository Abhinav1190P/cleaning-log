Assumptions, holes and what I would change. Assuming the audit requirement is scoped to cleaning records, not equipment, and that equipment deletion cascading to its records and audit logs is fine here even if a real regulated system would more likely block or soft delete instead. There's no role system yet, so status transitions between pending and verified aren't restricted. If I had more time I'd add real auth with role-gated verification, optimistic concurrency on updates (right now last write wins), keyset pagination if volume warranted it and more equipment CRUD integration tests. Omitted on purpose: soft deletes, file attachments, and a full docker compose run The file is what I verified locally (build, migrate, run), but I didn't have a docker daemon to actually run docker compose up itself.
